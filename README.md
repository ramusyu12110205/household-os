# Household OS

家計管理を行うWebアプリ。将来的に家計簿以外の管理機能を追加しても、既存機能を壊しにくい構造を目指す。

## 開発方針

- OS本体と家計簿アプリの責務を分ける
- 共通処理・共通UI・個別機能・画面を分離する
- 1つの巨大ファイルへ機能を追加し続けない
- 新機能は原則として `features/` に独立させる
- 既存機能への変更を最小限にする
- DBアクセスの責務を画面から分離する
- 仕様変更時は既存データとの互換性を優先する
- 実際に動いている機能を確認してから大規模な整理を行う

## 現在の構成

```text
household-os/
├─ index.html                 # アプリの入口
├─ css/
│  └─ style.css              # 共通スタイル
├─ js/
│  ├─ core/
│  │  └─ app.js              # 共通ユーティリティ・基盤
│  ├─ components/             # 複数画面で使うUI部品
│  └─ features/               # 家計機能
│     ├─ transactions/        # 支出・収入
│     ├─ budgets/             # 予算
│     ├─ credit/              # カード請求
│     ├─ assets/              # 資産・負債・口座
│     └─ settings/            # マスタ・設定
└─ README.md
```

## 移行方針

現在の家計簿は動作する既存実装を優先し、段階的にモジュールへ移行する。

1. 共通CSS・共通ユーティリティを整備
2. DBアクセス層を分離
3. 記録機能を分離
4. カード請求・資産・予算を分離
5. 画面単位の処理を分離
6. 最後に `index.html` を入口だけの薄いファイルにする

**重要:** 移行途中で既存の家計データやログインを壊さない。各段階で動作確認できる状態を維持する。
